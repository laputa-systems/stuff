# Fleet source audit

This review covers the default-branch source of all 72 managed repositories, including the selected private repositories. The table records the revision reviewed, the behavior selected by the test entry point, benchmark evidence, and typing gates or gaps. Executed checks from rollout work are recorded separately in [Fleet verification](fleet-verification-results.md). The source review did not run every suite, profile every benchmark, or establish exhaustive coverage of all typing boundaries.

All 72 reviewed defaults declare `make test` and `make clean`. Review the recipe and selected suite before treating a successful exit as a gate. Asterinas previously succeeded when workspace discovery selected zero packages. The pushed fix, `635c97e1118a`, passed three command-level cases covering empty selection, discovery failure, and dispatch with an eligible package. The kernel suite requires its own runner.

Thirty-nine repositories advertise a root benchmark target. The remaining 33 include repositories with other entry points or hardware gates, build repositories with artifact checks, and projects missing a representative timed workload. A list, dry run, preflight, or functional smoke does not establish a benchmark result. Run a named Change workload only on a host with the pinned candidate, fixtures, and any required baseline. Leave manually selected Full workloads to their documented operator gate.

The configured strict-typing rule and fork workflow naming rule yielded no findings. That policy result covers configured checks. The typing column records substantive gaps such as unchecked boundary payloads or missing execution on the supported runner. The [existing workflow gap list](fleet-verification-results.md) covers 16 first-party defaults. Private repositories remain part of local policy and dependency inventory regardless of hosted runner availability.

The [settlement and cleanup record](fleet-settlement.md) tracks the Stuff branches integrated or retained during this audit.

## Reproduce the review

From a clean canonical Stuff checkout, run `uv run repomod sync` and then run:

```sh
uv run repomod lint --include-private --rule make-test-target --rule make-clean-target --rule strict-typing-profile --rule gha-test-workflow --rule fork-workflow-names --json
```

For any finding on a checkout with local work, inspect the repository's `origin/HEAD` separately using `git show`. The checkout-based lint reported a stale test-target finding for SSH Build and a workflow finding on Chromium Build's active feature checkout. Both declarations are present on their reviewed default revisions. Inspect the invoked suite and one representative assertion, then trace benchmark timing output and the type checker through the test or CI entry point. Preserve the project's documented host and tier requirements.
