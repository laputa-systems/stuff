# Publisher test inventory

Scope: the DSLP-10 contracts in `crates/stuff` and their named external proofs. Paths below are relative to the repository root. The inventory records representative assertions, not an exhaustive list of input cases.

| Contract | Guarding tests | Gap and disposition |
| --- | --- | --- |
| Publish entry points | `crates/stuff/tests/cli.rs` checks help and parsing. `cargo_publish_e2e.rs`, `npm_publish.rs`, `pypi_publish.rs`, `pypi_first_party.rs`, `oci_publish.rs`, and `mirror_publish.rs` exercise each registry's publisher against isolated fixtures and fake storage. | Several scenarios call the library instead of the CLI. The CLI parsing and output tests complement those scenarios; retain both. |
| Exit codes and output | `publish_output.rs` asserts JSON and human outcomes, stdout and stderr, and codes 0, 2, 3, 4, and 5. `publish_retry.rs` checks conflicts and retry exhaustion. `cli.rs` checks documented failure mappings. | Output scenarios use OCI for the shared reporting path, not every registry and error combination. Retain the shared-path tests; no additional gap was demonstrated. |
| Cargo index and archives | `cargo_golden.rs` checks admission, rejection, index lines, shards, and checksums against `crates/mycrates/tests/golden/publish`. `cargo_render.rs` compares the complete rendered generation byte for byte with the mycrates golden generation and rejects missing or tampered blobs. `cargo_publish_e2e.rs` compares a native publication with the Python oracle. `cargo_lockfile.rs` checks verified upstream index lines, blobs, and checksum conflicts. | Fixtures do not enumerate every valid archive or manifest. Retain the independent oracle and rejection cases; no exhaustive input-space claim. |
| R2 storage and generation activation | `r2_client.rs`, `r2_put.rs`, `r2_multipart.rs`, and `r2_pull.rs` cover signing, retries, conditional writes, multipart upload, listing, and integrity. `r2_transaction.rs` covers upload order, manifest verification, activation, competing writers, interruption, and resumption. `r2_sync_concurrency.rs` checks manifest ordering and failure under concurrency. `fake_s3.rs` supplies the offline server. | Fake S3 cannot prove live R2 compatibility or every crash schedule. Needs environment: live R2 is explicitly outside this task; do not run `make test-r2-live`. |
| Republish and rollback | `republish.rs` compares rerendered Cargo, npm, PyPI, and OCI generations with their oracles and checks conditional promotion and a competing publication. `mirror_publish.rs` covers mirror republish. `rollback.rs` checks all registry targets, missing and corrupt manifests, missing OCI blobs, and competing promotion. `r2_transaction.rs` also checks rollback. | The matrix does not cover every failure for every registry. Retain shared transaction and representative registry tests. |
| Registry isolation | `make pipecheck` runs `deploy/check-pipeline-independence.sh`, compares local Cargo, PyPI, npm, and OCI site snapshots after other registries publish, and checks repeated generation determinism. | The script exercises registry builders rather than every `stuff publish` path, and omits mirror. Treat cross-registry publisher integration as an explicit unproven case; no demonstrated fault established a new test here. |
| Lock handling | `r2_transaction.rs` checks a held transaction lock and concurrent staging. `make test-publish-lock` runs `deploy/test-publish-lock.sh`, which checks serialization and shared locks among native publishers, Python helpers, shell helpers, and the container wrapper. `cargo_publish_e2e.rs` checks restoration of an existing workspace `Cargo.lock`. | The diagnosis reproduced a dry run with no prior `Cargo.lock`, but did not retain that test. Crash schedules and every lockfile restoration path remain unproven; retain existing checks. |

No test was added: this inventory found no demonstrated important gap with a fault witness. No hand-injected fault was run. Coverage and mutation measurement are **Needs environment**: `cargo-llvm-cov` and `cargo-mutants` are unavailable. No mutation lane is proposed; any future required lane needs explicit `scope` and `critical` selection under the gate rules. Offline fakes and the mycrates oracle do not establish production service behavior.
