# Repomod benchmark audit

At `96188b1038ac8bd8e26c0b50ce8a00240e93250a`, `make bench` invokes `bench/deps_perf.py phases --mode both --runs 3`. It measures the dashboard pipeline's load, visibility, live status and render wall phases, plus summed concurrent status work, against the tracked inventory. The phase subprocess records page and byte counts in JSON; the default table omits them. `make bench-cli` times the real `deps render --status` command, including process startup. Both report elapsed wall time, without a baseline, regression gate, distribution or process-tree resource accounting. Neither validates rendered content; `test_dashboard_preview.py` independently checks the preview fixture's presented content.

The existing commands lack `bench-check`, `bench-list`, tier and workload selectors, a dry run, selected-workload preflight, per-run logs and validity summaries. The harness collects live status and its real checkout paths, and cold runs may contact external services; it is not an isolated fixture. It has no CPU, memory, I/O or attribution measurements, so phase timing alone cannot explain resource regressions. A sampling profiler and process-tree resource measurements would be the cheapest follow-up. Sync, snapshot, CLI startup, and remote service latency have no isolated representative benchmark with a correctness oracle. The preview golden test checks correctness but is not a timed performance workload.

An entrypoint needs an Edit tier for selection and preflight tests, a Change tier for one short render workload, a Scenario tier for repeated reference comparisons, and a manual-only Full tier. `make bench` currently defaults to six phase measurements and has no such guard. The existing harness lives in `bench/`, outside this lane's writable paths. Its live status collection cannot be exercised here without touching canonical checkouts; replacing it with a synthetic result would not prove the same workload. No Edit or Change run was claimed. `perf-gate-ready` also reported a hot process tree on this host, so the working contract bars a timed performance gate until the host is quiet. No timing result is reported.

The smallest follow-up is to permit an isolated fixture in the existing harness and add the entrypoint and its tests, then prove Edit and one Change run on a ready host. Full remains manual-only. No performance conclusion follows from this audit.
